# 文档写作与验证

[文档首页](README.md)

文档的目标是让读者形成可以使用、推断和扩展系统的认识。项目首页说明定位与入口，共同概念建立词汇，使用者指南解释实际行为，开发者指南帮助构建应用，架构说明内部关系。参数和字段留在参考页，设计过程留在历史材料中。

## 章节的组织

以稳定主题组织章节，例如会话、工具、知识、装配和事件。开头说明本章对象及其与上一层的关系，正文解释行为、原因和边界，再给例子或进一步阅读。读者应能沿着章节理解一次工作，而不是先记住全部包名和类型。

使用者章节从实际操作写起，解释能观察到什么、怎样继续和结果意味着什么。开发者章节从完整可运行程序推进到扩展与宿主；不要把仓库贡献规范当成应用开发教程。架构章节讲控制流、状态归属和生命周期，源码路径只作为证据与阅读入口。

表格用于比较确实需要对照的选项；流程图用于解释分支、时序和多方关系。它们不能替代正文中的因果解释。FAQ 可以作为查阅补充，不作为整套文档的主结构。

## 行为的归属

| 内容 | 主要位置 |
| --- | --- |
| 框架、发行版、模型、会话、知识的关系 | 基本概念 |
| 安装、任务控制、工具使用、恢复、扫描与协作 | 使用者指南 |
| 扩展实现、配置接入、会话嵌入、协议宿主 | 开发者指南 |
| 装配、运行循环、执行、上下文与事件的内部契约 | 架构 |
| 参数、默认值、环境变量、协议字段 | 参考 |
| 版本变化、迁移背景、未采用方案 | Changelog、迁移文档与 RFC |

同一行为由一个主章节解释，其他章节通过链接提供所需深度。例如恢复的操作写在会话指南，事件文件与传输格式的区别写在数据架构；二者不再各复制一份完整教程。历史文档保留历史语境，不能作为当前实现的依据。

## 示例与事实

命令需要写明前置配置、工作目录、发行版和预期观察。示例中的目标与密钥使用本地或占位值。Go 教程优先链接仓库里的完整程序，正文只摘取解释所需的部分。

行为以当前代码和实际验证为准。声明了 flag、接口或配置字段，并不能证明对应执行路径已经接通；设计目标也不能写成现状。涉及迁移时明确当前入口、已实现部分和限制，发布版本的读者通过 Git tag 查看相应内容。

本次组织参考了 [Pi 的入口](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/README.md)、[SDK 教程](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/docs/sdk.md)与 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness/blob/master/README.zh.md) 的使用、开发和架构分层。参考的是阅读方式；Cyber 的显式线性装配仍按自身实现说明，不套用其他项目的插件生命周期。

## 验证

在仓库根目录执行：

```sh
node docs/check-links.mjs
go run ./examples/custom
go run ./examples/session
go test ./core/resource ./core/extension ./core/registry ./pkg/toolset ./examples/custom ./examples/session
```

链接检查覆盖根 README 和 docs 下的手写 Markdown，检查普通行内本地链接、标题锚点及代码围栏。生成式 API 目录不作为扫描源，代码块里的示意链接不检查；它不是完整的 Markdown/HTML 解析器，也不验证外部 URL 可达性。

两个例子分别验证工具注册调用和会话历史连续性。它们不调用远程模型，不验证供应商流式接口、Web 部署或实际目标扫描。修改相关集成行为时，需要补充对应验证并报告范围，不能用示例通过代替全部端到端验证。

移动页面时保留已发布入口或提供明确的迁移说明，并更新站内引用。修改行为时同时更新主要解释页和参数参考，提交说明包含具体变化、验证结果及尚未验证的边界。
