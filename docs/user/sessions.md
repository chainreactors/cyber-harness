# 会话与上下文

[使用者指南](README.md) · 前一篇：[Agent](../agent.md) · 下一篇：[工具](tools.md)

会话把多次输入组织成连续工作。你可以先让 Agent 分析一个目录，再要求它解释其中某个文件；第二次输入会使用已有的对话与工具结果。一次性命令完成任务后退出，交互模式则保留会话，等待下一次输入。

## 连续对话

启动 `aiscan agent` 后，普通输入会交给当前会话。模型每轮请求的上下文由指令、历史和工具结果组成，因此追问可以引用此前的结论。上下文中的描述不等于实时环境状态：如果文件或远程服务已经变化，Agent 需要重新读取或探测。

运行期间的追加输入在后续执行边界处理，不会修改已经发出的模型请求。`/followup <内容>` 明确将输入排队到当前任务完成后发送；`/continue` 则让 Agent 基于现有上下文继续工作，不追加新的任务说明。`/stop` 停止当前运行，不能撤销此前工具已经完成的文件写入或网络操作。

```text
aiscan> 读取当前目录中的报告，总结已经验证的结论
aiscan> /followup 再列出证据不足的结论
aiscan> /continue
```

后台命令与子 Agent 的完成结果也能回到会话。Agent 在等待这些结果时可能暂时没有新的模型输出；它仍然有尚未结束的工作。后台任务的查看与停止见[工具](tools.md#后台任务)。

## 周期提示

长任务也可以在会话中设置周期提示。`/loop 30s 检查当前任务是否有新结果` 每 30 秒将提示送回 Agent，`/loop list` 查看计划，`/loop stop <name>` 停止指定计划。实际工作仍由模型处理，不是 shell 定时直接执行。

周期计划保存在运行时内存中，不随历史恢复。活跃计划可能使 Agent 持续等待后续输入，完成工作后应停止计划。

`--heartbeat <分钟>` 使用同一调度机制，在主会话中周期提示 Agent 检查上下文与运行状态；默认 0 表示关闭。它会唤醒模型工作，不是仅用于网络保活。

## 上下文压缩

模型的上下文窗口有限。长时间工作后，早期对话、工具输出和新输入会共同占用窗口。自动压缩将较早内容总结为摘要，保留近期消息，再继续请求模型；手动压缩允许指定保留重点：

```text
aiscan> /compact 保留已验证结论、证据路径和未完成事项
```

摘要会损失细节。需要逐字引用的请求、响应、代码或命令输出，应保存为文件或原始产物。压缩不会让模型拥有无限记忆，也不会保证它在后续回答中还原所有原文。

`/clear` 清空当前上下文，适合开始不相关的工作。它与压缩不同：压缩保留继续任务所需的摘要，清空则放弃当前对话上下文。两者都不等同于回滚工具对外部环境的修改。

`context_window` 表示模型请求窗口，`max_tokens` 控制单次最大输出。二者不能用来直接表示整个任务的费用预算。字段和模型配置见[参考手册](../reference.md#llm-协议与-profile)。

## 记录

CLI 使用 `-o` 将运行事件保存到新建的 ProtoJSONL 文件：

```sh
aiscan agent -p "读取当前目录并总结" -o first.jsonl
```

记录包含运行时发出的消息、工具调用、结果与生命周期等事件。需要文件、HTTP 等额外观察时，可使用 `--observe` 选择观测项；保存记录不会自动开启所有观测。重复运行应换一个输出路径，已有文件不会作为追加日志继续写入。

`--output-format` 只控制 one-shot 的标准输出：`text` 用于阅读，`json` 返回一次任务的结果对象，`stream-json` 输出事件流。扫描器的 `-j` 则是各自的结果格式。这些输出与 `-o` 的历史文件用途不同，不能仅凭都是 JSON 就互换。

## 回看与恢复

回看读取事件并渲染，不运行模型或重复调用旧工具：

```sh
aiscan -F first.jsonl
aiscan -F first.jsonl --view-format markdown -f first.md
```

恢复从事件历史中建立对话上下文，再执行新的输入：

```sh
aiscan agent --resume first.jsonl -p "继续解释刚才的结果" -o second.jsonl
```

交互模式也可用 `/resume` 选择记录，或用 `/resume <路径>` 指定文件。恢复源保持只读；若要保存后续运行，需要另外指定输出。Web 的会话历史由 Web 数据库管理，不能直接把数据库文件作为 CLI 的 `--resume` 输入。

恢复的对象是对话历史。旧的终端进程、浏览器实例、IOA 连接和周期任务不会因此重新出现。恢复后涉及环境状态的工作，应先确认现状，再决定是否重新执行。

## 结果与证据

最终回答是模型对工作结果的解释，工具产物是执行留下的数据。安全扫描中，端口、指纹和漏洞发现还会进入专门的结果视图；一个模型结论不自动变成已验证漏洞，资产视图为空也不等于没有发生工具执行。

需要交付或复核时，同时保留结论、证据位置和验证范围。内部事件格式及资产生成过程见[事件与持久化](../architecture/data.md)，日常扫描输出见[扫描指南](../scan.md#输出格式)。
