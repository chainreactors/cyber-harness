# 基本概念

[文档首页](README.md)

cyber-harness 是让模型在实际环境中工作的运行框架。模型能够理解任务、生成回答和提出工具调用；框架负责组织上下文、执行调用、把结果交回模型，并管理这段工作需要的会话、资源和记录。

## Harness 与 Agent

单次模型请求以一组消息为输入，以回答或工具调用为输出。Agent 将这些请求连接起来：模型请求读取文件，框架执行读取并返回内容；模型根据内容决定下一步，可能继续调用工具，也可能给出最终回答。这个反复推进的过程称为 Agent 循环。

Harness 为循环提供可工作的环境。除了工具，它还处理模型连接、消息历史、运行中的追加输入、后台工作和取消。因而同一个模型在不同 harness 中可以表现出不同的工作能力：差异既来自提示词，也来自它实际能调用什么、收到什么结果，以及运行过程怎样被管理。

## cyber-harness 与 aiscan

cyber-harness 提供可复用的运行机制。`aiscan` 将这些机制与安全扫描器、领域知识、代理和协作能力组装在一起，形成可直接运行的产品。`aiscan-full` 在此基础上增加 Web 工作台、浏览器自动化、被动测绘和深度爬取等能力。

使用者通常通过 aiscan 的命令行或 Web 工作。开发者可以嵌入这套发行版，也可以选择一组更小的能力，构建自己的 Agent 应用。源码中的最小 Agent 就是一种不同的组合。

## 模型与工具

模型通过工具影响环境。一个工具有名称、说明、参数结构和执行实现；模型根据这些信息生成调用，harness 校验并执行，再把结果加入对话。文件读取、shell 执行和子 Agent 都可以作为工具。

aiscan 还支持命令式工具。模型可以调用 `bash` 并传入 `gogo ...`，harness 将这个命令路由到已注册的扫描器；调用普通 shell 命令时，则由宿主启动外部程序。这使内置能力和现有命令行工作流能够共同使用。

工具结果是下一步判断的依据，但一次调用成功并不自动证明任务已经完成。模型需要解释结果，使用者也需要根据证据判断结论。目标评估可以在执行之后增加一层验收反馈。

## 会话与上下文

会话让多次输入形成连续工作。模型每次请求仍然只看到当时传入的上下文，其中包含系统指令、对话历史、工具结果和需要的知识。会话负责将这些内容组织起来，使“继续刚才的分析”有可以依赖的历史。

历史越长，占用的上下文越多。压缩将早期内容总结为摘要并保留近期消息，以便继续工作；记录则保存运行事件，供回看或恢复。摘要可能丢失细节，原始证据应保存在文件或工具产物中。恢复对话也只恢复历史，不会重新创建过去运行的进程和连接。

## Skills 与知识

工具提供执行能力，Skill 提供使用能力的方法。一个 Skill 可以告诉模型怎样分析报告、何时调用扫描器，以及应当阅读哪些参考资料。它本身是带元数据的文档，加载后成为模型可使用的知识。

参考发行版通过 `cyber` Skill 组织领域知识，详细工具说明按需读取。部分知识使用 OKF（Open Knowledge Format）组织为带索引、概念和来源信息的文档集合。修改知识可以改变模型的工作方式；实际能够执行的操作仍由已安装的工具决定。

## 扩展与应用

扩展是把一项能力接入应用的组合单元。它可以贡献工具、知识或提示词，也可以持有模型连接、终端和服务等运行资源。应用选择扩展并管理它们的加载与关闭。

“一切皆扩展”描述的是产品能力的组装方式。业务实现仍可写成普通 Go 代码，再由扩展接入框架。cyber-harness 的扩展随应用静态编译；具体装配机制见[架构](architecture.md)，开发过程见[开发者指南](development.md)。

## 安全扫描与协作

安全工具既可由 Agent 根据任务逐步调用，也可由 `scan` 按确定的规则编排。后者根据端口、Web 服务、指纹等发现触发后续阶段，并可在指定阶段加入 AI 验证。二者共享工具基础，但安排工作的方式不同。

更复杂的工作可以交给本地子 Agent，或者通过 IOA 与其他 Agent 交换消息。Web 则提供会话和节点的操作界面，允许任务在远程节点执行。对话、协作消息与执行节点分别有自己的状态，相关使用方法在[使用者指南](user/README.md)中继续展开。
